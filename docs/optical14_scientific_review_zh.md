# 14 种触觉算子的科学验收与迭代结论

2026-09-06；适用版本：`optical_marker_v1`。保留 14 个 ID，不自动改变
旧 registry、模型训练/推理环境、已有闭环实验或论文中的历史结果。

## 判断：能用于哪一种论文主张

**可以作为可复现的观测层故障 benchmark；还不能作为真实材料失效的
定量模拟器。** 前者需要明确的干预对象、可测签名、因果时序和对照；
后者还需要真实硬件、已知接触/载荷和参数标定，漂亮图片不能替代。
当前实现支持 G0/G1 范围的机制合理性与可执行性，不证明真实损伤等价性，
不保证同行评审接收，也不提供新的闭环鲁棒性指标。

本轮验收依次区分五件事：代码是否按定义运行；观测是否确实变化；变化
是否符合所声称的信号机制；是否对应真实故障；是否影响任务表现。
前两项通过不自动推出后三项；损伤可见也不必然让任务失败。

## 文献给出的约束，以及本实现的取舍

| 证据 | 对本 benchmark 的直接约束 |
|---|---|
| [Taxim, Si 与 Yuan，2022](https://arxiv.org/html/2109.04027) 分别建模光学响应与弹性 marker 位移 | RGB 与 marker 提供不同读出，但在真实传感器中共享接触形变；保留当前 marker 只能称光学通道隔离，不能声称完整材料失效 |
| [PolyTouch，ICRA 2025](https://arxiv.org/html/2504.19341v1) 讨论 VHB 的黏弹恢复和慢响应，并指出照明引发的图像饱和 | F6 慢恢复有现实现象依据，但不能据此给 UniVTAC 的胶体指定相同时间常数；照明过曝与本 F7 的残差压缩是不同机制 |
| [Agarwal 等，2025](https://arxiv.org/html/2504.14739v1) 的光学仿真包含曝光、clipping 与 bloom | 相机饱和发生在曝光/绝对辐射响应链；本 F7 不实现该链，不能解释为过曝白斑 |
| [Davis 与 Stuart，2025 预印本](https://arxiv.org/html/2511.07797v1) 在已知压头与同步力测量下评价灵敏度、饱和及磨损 | 图像平均差不等于压力或灵敏度标定；应测局部响应、已知空间信号或已知载荷下的传递关系，不把其他传感器的 N 数值搬过来 |
| [Cottrell 等，2026-08-25 预印本](https://arxiv.org/html/2608.24242v1) 讨论磨损、撕裂、脱层与成像可用性 | 一条可见痕迹不必导致明显成像/任务退化；不可把“必须降低 SR”作为调强度的验收准则 |
| [TactileGenesis，2026 预印本](https://arxiv.org/html/2606.22332v1) 使用带时间常数的读出迟滞代理 | 显式源时间与动态状态是合理实现形式，但该工作不标定本 RGB 代理的恢复时间，也不证明 RGB dead patch 等价于其他模态的 dead taxel |

这些来源支持故障类别或方法边界，不支持本项目全部参数、局部 mask 形状
或损伤幅度已由文献验证。预印本与已发表文献在表中明确区分。

## 逐类验收意见

| 算子 | 本轮结论 | 允许的解释 / 不能越过的边界 |
|---|---|---|
| A1 / A2 | 适合观测层 benchmark | 连续缺失 / 间歇缺失；依据 presence 和恢复时序，不能用黑图冒充结构缺失 |
| F1 | 适合光度漂移代理 | 通道 gain/offset 漂移；未标定温度或 LED 老化的具体幅度 |
| F2 | 适合局部光学灵敏度衰减 | 固定中心区域，压低相对零压入光学场的响应；marker 与 mask 外不变，不称法向力减小 |
| F3 | 适合持久表面外观伪影 | 程序化 scar 是可控干预；不声称复现特定裂纹/磨损材料的形貌分布 |
| F4 | 适合局部光学失响应 | 光学场 stuck-at-rest，当前 marker 仍可动；因此不是该区域全部触觉信息失效 |
| F5 | 适合一致坐标形变代理 | 当前图像与唯一 marker 阵列经过同一无折叠映射；不等价于重求接触力学及光照 |
| F6 | 有条件适合历史光学残痕 | 记录样例只证实局部卸载；完整恢复曲线用明确标注的 analytical stimulus 检查，不能包装成实测材料迟滞 |
| F7 | 适合高响应非线性压缩 | 原 ID 保留；展示名应写“高响应光学压缩（饱和代理）”，不是压力饱和或曝光 clipping |
| T1 / T2 / T3 | 适合观测层 benchmark | 共同延迟 / 固定旧源帧后恢复 / 单侧延迟；以源时间、到达时间、payload hash 区分，T3 不冒称随机 jitter |
| C1 / C2 | 适合路由/注册失配 | 来源交换 / 像素坐标错位；不是在引擎里重新装配传感器 |

14 种类别覆盖本项目选定的 availability、fidelity、temporal、contextual
观测故障面，不声称穷尽所有传感器硬件、材料与通信失效。

## 本轮实际迭代

1. 继续使用修正后的零压入参考：来自 pinned 官方 Taxim 光学标定资源，
   **不是** key55/HDMI90 中实际记录的无接触图。原始深度已表明这两个
   episode 一直存在接触；把“低变化帧”当无接触会引入错误物体轮廓。
2. 不再用全图平均像素差解释 F2/F4 的灵敏度。对非 marker、clean 响应
   范数大于 `2/255` 的有效像素，测 flat-core 内的投影 gain：
   `sum(R_clean · R_delivered) / sum(||R_clean||²)`。该阈值只是测量底噪，
   不代表接触力；统计范围是窗口内有效接触样本，不是只挑展示帧。
3. 添加五种不适用反例：F2/F4 的 ROI 无接触响应、F5 无 contact phase、
   F6 无先前接触、F7 未达到 knee。原总校验器本已拒绝零效果；此次补充
   精确原因码与有效像素计数，而非声称发现了一个“全部误判通过”的 bug。
4. F6 增加受控加载—保持—完全释放信号，在 60/120 Hz 下检查同一物理
   时间的残差、衰减和新 episode 状态清空。不同历史、相同当前 rest
   必须得到位置不同的残痕；identity delivery 负对照必须失败。
5. F7 增加输入—输出传递曲线，检查低响应恒等、高响应 gain 减小、单调
   与有界。baseline 从 100 改为 130 而残差相同时曲线重合，恰好说明
   本实现是**相对响应压缩，而不是绝对亮度 clipping**。

本轮没有为了让图片更夸张而再次增大强度，也未修改生产像素变换。
新的改动是可测量性、拒绝原因与反例测试。全部科学曲线由正式 delivery
输出计算；analytical stimulus 单独保存、显著标注，不混入记录样本图集。

### 实测结果和看图后的再迭代

| 检查 | 本轮结果 |
|---|---|
| F2 core gain，S1–S5 | 0.9035 / 0.7504 / 0.5515 / 0.3005 / 0.0969；目标为 0.90 / 0.75 / 0.55 / 0.30 / 0.10 |
| F4 core gain，S1–S5 | 全部为 0；severity 增强的是失响应面积，不是继续把零 gain 降低 |
| F2/F4 控制区域 | mask 支撑外改变像素数为 0；F2/F4/F6/F7 当前 marker 改变元素数均为 0 |
| F6 analytical，S5 | 60/120 Hz 下均测得残差降低 50% 用时 1.65 s、降低 90% 用时 5.6333 s；两时钟最大差 0.005966，低于 RGB 量化界 0.006792 |
| F7 analytical，S5 | 高幅输入范数 0.52613 → 输出 0.04738；低幅恒等、高幅压缩、有界与 baseline 不变性均通过 |
| Gallery | 14 个实例 + 20 个 severity 实例通过；47 个输出 hash、85 个生产源/schema hash 一致 |
| 聚焦回归 | 67 tests、296 subtests 通过；optical 包与 assessment 脚本 Ruff、strict mypy 通过；未运行整库回归 |

F6 的工程设定 `tau=2.4 s` 对应理论 t50=1.6636 s、t90=5.5262 s；
实测值来自量化后的 RGB，不抹去它与连续曲线的差异。

我检查全图后认为 F2 的局部变化仍不够方便读者观察，因此增加了
`F2_detail.png` / `F4_detail.png`。它们只把同一个固定 ROI 按最近邻放大
3 倍：左侧上下文标出位置，后面并列 Clean / S3 / S5；四次 delivery
重放的 trace hash 与 gallery 完全一致。该迭代改的是解释方式，未改
颜色、对比度、展示帧或算子强度。

放大图也揭示了代理的限制：marker 周围的保护 guard 会保留少量原始
颜色，高强度下可能出现局部色边。因此这类图适合说明明确限定的光学
通道干预，**不适合单独作为材料形变物理一致性的证明**。F6 的记录
单帧只作局部卸载示例；完整恢复主张必须看独立标注的受控时序曲线。

## 可复现产物与解释规则

在 [复现入口](optical14.md) 完成 source preparation 后，执行：

```bash
PYTHONPATH=src python scripts/visualize_optical14.py \
  --source-root deployment/artifacts/optical14-sources/calibrated_standalone_v1 \
  --output-root deployment/artifacts/optical14-gallery-v7science

PYTHONPATH=src python scripts/assess_optical14.py \
  --gallery-root deployment/artifacts/optical14-gallery-v7science \
  --source-root deployment/artifacts/optical14-sources/calibrated_standalone_v1 \
  --output-root deployment/artifacts/optical14-scientific-v2detail
```

输出目录必须不存在。`assessment.json` 记录源代码、gallery 和图文件
SHA256，以及 `observation_level_acceptance_passed`；后者只表示本页列出的
观测层检查，物理标定、闭环结果和论文接收的状态另行明确为 false。
`analytical_probes.json` 保留所有曲线、阈值、pass/fail 和原始数值。
输出失败不允许用旧目录里的漂亮图替代通过证据。

本轮最终判定为 `observation_level_acceptance_passed=true`；
前一轮科学面板 `optical14-scientific-v1` 与旧 gallery 均保留，不覆盖。

## 我不建议继续“看图调强度”的部分

当前两段记录是开发样例，不是独立测试集。F2/F4 的局部干预、F6 的时间
状态和 F7 的传递关系可以验证，但还缺以下论文证据：

- 冻结参数后，在未参与选帧/调参的多 episode、多任务上报告适用率和
  信号签名，而不只展示两张最明显的图；不适用与政策执行失败分开。
- 若要声称物理忠实，补真实传感器的零接触—已知压入/载荷—保持—完整
  释放记录，拟合并在独立条件下验证 F6/F7；不能靠算法生成尾巴来填缺。
- 主文和附录旧实现描述要与新 registry 对齐，特别是 F4 的 marker、
  F6 的时间常数/局部卸载、F7 的 soft-knee。不能把新图配到旧公式上。
- 闭环实验继续使用相同 production path，报告 Clean/Faulted、配对种子、
  置信区间和触觉因果诊断。SR 是否下降取决于任务/策略是否使用相关信息，
  不能反过来作为无限加大干预的理由。

以上是证据扩展，不是要求反复初始化模型或重做已经跑通的环境。

## 投稿图示的第二次验收：不把运行通过当成主图合格

对照顶会审稿中可解释性与证据边界的要求，重新看图后的取舍如下：

- **主面板认可 F4、C2、T2、T1/T3。** 分别以局部特征消失、全局30 px
  注册平移、旧帧冻结后恢复、共同延迟与单侧延迟解释不同机制。
- **F2 暂不作裸眼显著性主图。** 即使 ROI 放大，主体结构仍相近；使用
  定量响应曲线作辅助证据，不再增强颜色来制造视觉冲击。
- **F6 暂不作真实完全释放主图。** 记录中只有局部卸载；受控恢复曲线与
  实际记录的证据性质必须分开，不借图片替代缺失的释放数据。
